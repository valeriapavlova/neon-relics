# NEON RELICS — контекст для Claude Code

Концептуальний онлайн-магазин прикрас. Проєкт портфоліо Валерії Павлової (UX/UI-дизайнерка і веб-розробниця, CEI Valencia).
Демо: https://valeriapavlova.github.io/neon-relics/ · Figma: https://www.figma.com/design/6uNtfQ3dKm1cZS6wZYT92j/Neon-Relics

## Стек і правила коду
- Чистий HTML + CSS + JavaScript (ES-модулі). **Без фреймворків, без збірки, без npm-залежностей.** Сайт живе на GitHub Pages.
- Точка входу JS: `js/index.js` імпортує модулі й запускає їх залежно від сторінки.
- CSS в одному файлі `css/styles.css`, з nesting (`&`) і BEM-подібними класами (`block__element--modifier`).
- **Не використовувати `!important`.** Конфлікти вирішувати специфічністю і чистішими селекторами.
- Використовувати наявні токени з `:root` (`--c-*`, `--space-*`, `--f-*`, `--fs-*`). Не хардкодити кольори й відступи.
- Коментарі в коді іспанською, як у решті проєкту.
- Шляхи до файлів **тільки відносні без `../` в HTML** (сайт відкривається з підпапки `/neon-relics/`). У CSS шляхи від `css/`, тобто `../assets/...`.
- Зображення у WebP, відео WebM + MP4 (H.264) як резерв. Нові медіа стискати (відео до ~2 МБ, 1080p, 30 fps).
- Доступність: alt у кожного змістовного зображення, видимий `:focus-visible`, усе керування доступне з клавіатури, `prefers-reduced-motion`.
- Брейкпоінти дизайну: 1440, 1024, 768, 375. На 375 px не має бути горизонтального скролу.

## Дизайн-система
- Кольори: фон `--c-bg #D8DFE6`, акцент `--c-primary #CC230F` (+ `--dark #A41F10`, `--soft #E08C82`), текст `--c-text #0F1821`, `--c-text--muted #82868B`. Темні «вітрини» для фото: `#0B1118` / `#0F1821`.
- Шрифти: **Unbounded** 500/600 для заголовків (uppercase), **Jost** 400/500/600 для тексту.
- Стиль: мінімалізм, багато повітря, великі червоні заголовки, фото на темних панелях, тонкі лінії-роздільники.

## Нова концепція (листопад 2026)
Замість 12 випадкових товарів буде **капсульна колекція: 4 образи (персонажі), у кожного 1–3 прикраси**, разом 6–8 прикрас.
Еталон поведінки й верстки — **`docs/capsule-prototype.html`** (робочий прототип; масив `IMG` усередині містить base64-заглушки, його можна ігнорувати). Структуру, тексти й логіку брати звідти, а стилі адаптувати до токенів `styles.css`.

### 1. Секція «Featured» на головній (`#collection`)
- Сітка з 4 карток образів «сходинками» (`js/featured.js`): 4 колонки на десктопі, 2 на планшеті, 1 на мобільному.
- Картка: «Look 01» + кількість прикрас, фото персонажа (3:4, темний фон), назва образу, рядок «Персонаж. Слоган». При hover фото темнішає і знизу з'являються мініатюри прикрас.
- Клік веде на `product-card.html?look=<id>`.

### 2. Картка образу (`product-card.html` + `js/product.js`)
- Ліворуч фото персонажа (sticky на десктопі), праворуч: ім'я персонажа (eyebrow), назва образу (великий червоний заголовок), теги настрою, історія.
- Темна панель «Worn in this look» зі списком прикрас: фото, назва, опис, матеріал, тираж («1 of 12»), ціна і кнопка **«Keep in capsule» ↔ «In capsule ✓»** (`aria-pressed`).
- **Лічильника кількості (− 1 +) немає.** Кожна реліквія одна. Якщо прикрас більше однієї, є кнопка «Keep the whole look».
- Внизу навігація між образами: попередній / наступний.

### 3. Капсула (`capsule.html` + `js/capsule.js`)
Текст сторінки: *Instead of a classic cart, each selection is kept in your capsule: an intimate inventory of pieces that resonate with you. Add, remove, reorder. You are not buying impulses; you are curating a small archive of power.*
- Нумерований список (порядок = вибір користувачки). Перестановка: drag & drop + кнопки ↑↓ для клавіатури.
- У кожної прикраси поле-нотатка «Why it resonates…», зберігається.
- «Release» прибирає прикрасу, з'являється рядок «Undo».
- Темна панель «The archive»: скільки реліквій із загальної кількості, скільки образів представлено, загальна вартість.
- Замість checkout: форма «Seal my capsule» (ім'я + email, валідація в клієнті) → стан «Capsule sealed» з повідомленням про приватний перегляд.
- Порожній стан: «The archive is empty» + кнопка до колекції.
- Дані в `localStorage`, формат `[{ id, note }]`. Читання й запис обгорнути в `try/catch`. Старий формат з `quantity` мігрувати або очистити.
- Лічильник у хедері (`.wishlist-counter`) показує кількість реліквій.

### 4. About (`about.html` + `js/about.js`)
- За фреймом `about` у Figma. Зображення в `assets/img/about-page/`, відео карток 006 і 008 у `assets/videos/about-page/` (WebM + MP4, відтворюються тільки без `prefers-reduced-motion`).
- Фон блоку Philosophy з паралаксом (`background-attachment: fixed`), як секція manifest на головній.

### Дані
Один файл даних `js/data.js` з масивами `LOOKS` і `PIECES`, як у прототипі. Усі сторінки читають звідти. Фото поки старі (заглушки), потім Валерія підставить нових AI-персонажів, тому шляхи до зображень мають бути тільки в даних.

## Git: гілки, коміти, PR
Валерія вчиться працювати з Git, тому дотримуйся цих правил завжди й коротко пояснюй, що робиш.

### Гілки
- **Ніколи не комітити й не пушити прямо в `main`.** Кожна задача — окрема гілка від свіжого `main`:
  `git checkout main && git pull && git checkout -b <тип>/<коротка-назва>`
- Назва гілки: англійською, kebab-case, з префіксом типу: `feat/look-page`, `fix/capsule-counter`, `style/featured-grid`, `docs/readme`, `chore/compress-images`.

### Коміти — Conventional Commits, іспанською
Формат: `<тип>(<область>): <що зроблено>`
- **Типи:** `feat` нова функція · `fix` виправлення бага · `style` тільки CSS/вигляд · `refactor` переписаний код без зміни поведінки · `perf` швидкість/вага · `docs` документація · `chore` службове (файли, налаштування) · `a11y` доступність
- **Область (необов'язково):** `capsule`, `look`, `featured`, `header`, `footer`, `events`, `about`, `data`, `assets`
- **Опис:** іспанською, з малої літери, в інфінітиві, без крапки в кінці, до ~70 символів. Пояснює *що* змінилось, а не *як*.
- Якщо потрібно, після порожнього рядка тіло коміту зі списком змін (`- ...`).

Приклади:
```
feat(capsule): añadir reordenación con drag & drop y botones ↑↓
fix(look): redirigir a la colección si el id no existe
style(featured): ajustar la cuadrícula escalonada en tablet
refactor(data): mover LOOKS y PIECES a js/data.js
a11y(capsule): añadir aria-pressed a los botones de la cápsula
perf(assets): convertir retratos a WebP 1200×1600
```

### Як комітити
- **Маленькі логічні коміти:** один коміт = одна зміна, яку можна описати одним рядком. Не змішувати в одному коміті дані, стилі й нову функцію.
- Перед комітом: пройти «Перевірку перед комітом» (вище), подивитися `git status` і `git diff --stat`, не додавати зайве (`.DS_Store`, тимчасові файли, скріншоти).
- Додавати файли поіменно (`git add js/capsule.js css/styles.css`), а не `git add .` наосліп.
- **Перед кожним комітом показати Валерії список змін і запропонований меседж**, і комітити після її «ок».

### PR
- Після завершення задачі: `git push -u origin <гілка>`, потім дати Валерії посилання на створення PR:
  `https://github.com/valeriapavlova/neon-relics/pull/new/<гілка>`
- Назва PR як у головного коміту. В описі: що зроблено (список), як перевірити (які сторінки відкрити), скріншот до/після, якщо змінився вигляд.
- PR зливає сама Валерія на GitHub. Після злиття: `git checkout main && git pull` і видалити локальну гілку (`git branch -d <гілка>`).
